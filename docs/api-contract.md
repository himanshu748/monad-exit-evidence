# UI API contract (v1)
All responses: `{data: VALUE|null,error:null|{code:string,message:string},meta:{receivedAt:string}}`.

- GET /api/health -> `{mode:'READ_ONLY', tradingEnabled:false, integrations:{perpl:'live-public-read',envio:'unavailable'|'live',cre:'login-required',nansen:'access-required'}}`
- GET /api/markets?network=mainnet|testnet -> `{network,chainId,source:'PERPL_PUBLIC_API',sourceUrl,receivedAt,observedAt,stale:boolean,markets:[{id:number,name:string,symbol:string,sizeDecimals:number,priceDecimals:number,markPrice:string,bidPrice:string,askPrice:string,openInterest:string,dailyVolume:string,fundingRate:string,isOpen:boolean,observedAt:string}]}`. Prices and amounts here are human-formatted decimal strings. No fabricated fallback quotes. Market `name` can be BTC or BTC Perp; symbol falls back to size_units.
- GET /api/liquidity?network=&marketId=1&quantity=0.02&direction=long -> `{network,chainId,marketId,source:'PERPL_PUBLIC_API',sourceUrl,receivedAt,observedAt,stale:boolean,sizeDecimals,priceDecimals,bids:[{price:string,quantity:string}],asks:[{price:string,quantity:string}],estimate:{requestedQuantity:string,availableQuantity:string,estimatedFilledQuantity:string,estimatedAveragePrice:string|null,worstPrice:string|null,depthLimited:boolean,meaning:string}}`. Estimate is a snapshot calculation, never a fill guarantee; long exit consumes bids, short consumes asks.
- GET /api/activity?network= -> `{status:'live'|'unavailable',source:'ENVIO',chainId,watermark:number|null,receivedAt,events:[{id,transactionHash,blockNumber,logIndex,kind,marketId:string|null,accountId:string|null,quantity:string|null,source:'ENVIO'}],error?:string}`. Empty/unavailable stays explicit.
- POST /api/rehearsals with header Idempotency-Key UUID and JSON RehearsalInput -> Receipt from src/core/types.ts. Quantity/price form fields are human decimal strings. sizeDecimals/priceDecimals from selected live market; server checks precision against live cached context. Receipt quantities are integer base-unit strings; format using retained market precision. All approvals and execution are REPLAY. Scenarios: valid, unauthorized, partial, interrupted, duplicate, tampered. For tampered, server returns a deliberately changed filledQuantity but original digest, so verify should fail.
- POST /api/receipts/verify JSON `{receipt:Receipt}` -> VerificationResult. SHA256 consistency is integrity only, never real financial execution/authentication proof.
- GET /api/nansen/status -> `{status:'access-required',source:'NANSEN',message:string}` initially; never a live badge.

Changing network/market invalidates the reviewed form and previous receipt context. Include literal 'Hypothetical position' and 'Simulated approval and execution' near primary action. Button should say 'Review limits' then 'Run rehearsal', never sign/trade. Failures should retain form and show errors. Currency formatted for display only. Persistent unknown/partial warning. Receipt export should contain unchanged returned JSON.
